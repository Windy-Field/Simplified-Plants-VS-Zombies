# 游戏界面设计

## 阳光数字

选卡、开场卡槽和战斗共用 `GameRenderer.drawSunNumber`，数字区域由 `Layout` 统一维护，阳光收集的终点也从这个区域中心计算

根据最新要求，阳光数字恢复修改前的样式：数字框左上角为 `(31, 66)`，大小为 `32×17`，固定使用 19 号字体，右对齐，基线位于框顶下方 15 像素。不再执行字形居中或自动缩放，长数字也沿用旧版表现

## 关卡选择

- 主菜单点击“冒险模式”，进入选关页
- 每页显示六关，单击封面选中，再点击“开始”进入该关；双击同一关卡封面可直接进入开场和选卡流程
- 方向键切换关卡，Page Up / Page Down 翻页，Enter 开始，Esc 返回
- 关卡文件按实际编号读取和排序，中间缺号不影响其他关卡显示
- 原命令行关卡参数决定默认选中的关卡；编辑器“保存并试玩”仍直接进入当前关卡
- 通关自动继续下一关的原有流程保持不变
- 选卡、开场演出和战斗的最右上角显示“返回选关”，距右边缘 4 像素，倍速按钮位于它左侧；点击或按 Esc 放弃当前一局并返回选关，默认选中刚退出的关卡
- 返回时清空植物、僵尸、子弹和手持工具，重新开始从关卡初始状态载入，不恢复中途进度
- 标题、按钮与关卡名称使用同一个文字布局对象测量和绘制，在逻辑坐标中按字形居中，避免系统缩放时把物理像素误当作逻辑像素

## 素材与封面

选关背景、边框和按钮引用已有资源：

| 用途 | 素材路径 |
| --- | --- |
| 原版选关背景 | `assets/new_assets/UniqueAssets/Props/LevelSelector.jpg` |
| 关卡边框 | `assets/new_assets/UniqueAssets/Props/LevelPanel.png` |
| 控制按钮 | `assets/new_assets/UniqueAssets/Props/Button.png` |

选关页优先使用编辑器设置的截图。没有设置、图片丢失或图片损坏时，`LevelPreview` 根据关卡 JSON 的背景、卡槽、卡池、禁用名单和实际僵尸品种构造静态战场，再通过原 `GameRenderer` 绘制自动封面。自动封面属于代表性战场预览，不是玩家历史存档截图

## 编辑器截图设置

在右侧“关卡参数”的“关卡截图”区域点击“选择截图”，可导入 PNG、JPG、JPEG 或 GIF 图片，GIF 使用第一帧。导入成功后显示预览，点击“保存关卡”后选关页才会使用该设置

图片统一转为 PNG，保存到 `assets/levels/screenshots/screenshot_<唯一编号>.png`，原图片不改动。关卡 JSON 的 `screenshot` 字段只记录相对于 `assets` 的路径，例如 `levels/screenshots/screenshot_....png`，因此移动整个项目后不依赖原电脑上的图片位置

点击“恢复自动”会清空当前关卡的截图设置，保存后恢复自动封面。恢复自动不删除图片文件，因为其他关卡可能仍引用同一张图。新建关卡会清空设置，打开和另存关卡会保留截图字段

截图在编辑器和选关页都按原比例缩放并居中留边，不拉伸。截图无法读取时编辑器显示提示，游戏继续使用自动封面。参数区域支持独立滚动，避免截图预览把编辑器窗口撑出屏幕

自动封面只保存在内存，打开选关时重新生成，不向源码或素材目录写入生成图片；用户主动导入的截图保存在上述素材目录。编辑器保存后再次进入选关即可看到新配置

## 主菜单图鉴

主菜单右下方的书本是图鉴入口，使用原有 `SelectorScreen_Almanac.png` 上半部分作为按钮。图鉴内使用已有植物、僵尸背景和详情卡素材，不新增重复图片

- 植物页列出资料表中全部 21 种植物，包括两种保龄球植物；僵尸页列出已实现的 9 种僵尸
- 单击条目切换详情，左侧为静态缩略图，右侧持续播放该品种 GIF 的解码帧
- GIF 复用现有 `Assets` 数据，动画时间使用游戏现有时钟；不会创建植物或僵尸战斗对象
- 血量、阳光花费、冷却、移动速度与伤害读取当前游戏资料和常量，能力说明放在 `AlmanacDescriptions.java`
- 支持植物／僵尸切换、分页、暂停动画和返回主页；方向键选择，Page Up / Page Down 翻页，Tab 切类别，空格暂停或继续，Esc 返回
- 动画按整段可见范围缩放，避免切帧时体型跳动；长名称和介绍自动适配固定区域
- 动画窗口引用游戏草坪素材：小喷菇、胆小菇、阳光菇、寒冰菇和魅惑菇使用黑夜草坪，其余植物和僵尸使用白天草坪；复用植物的白天睡眠标记切换背景，不另存重复图片

`Almanac.java` 负责只读浏览和绘制，`AlmanacDescriptions.java` 负责中文介绍，`Game` 只负责图鉴入口、时钟重绘与返回主页

## 传送带入场与排队

传送带和保龄球开场顺序为：镜头移回草坪并停稳，卡槽从顶部滑入 500 毫秒，卡槽到位后开始三秒倒计时，最后启动战斗和补卡。普通选卡关卡保留镜头返回后直接倒计时的流程

传送带的卡片排队使用 `Card.bounds` 的实际绘制宽度，相邻卡片边缘留出 4 像素。入口位置由底板右边界减去新卡宽度确定，满队列不继续补卡；使用中间卡片后，后面的卡片逐步前移，同时遵守前一张卡片的实际右边界

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `game/Game.java` | 画面切换、事件分派与关卡启动 |
| `game/LevelSelection.java` | 选关布局、选中、翻页与绘制 |
| `game/LevelPreview.java` | 根据实际关卡资料制作封面 |
| `level/LevelLoader.java` | 读取关卡内容与发现编号 |
| `level/LevelScreenshot.java` | 截图导入、相对路径读取和等比例适配 |
| `world/Assets.java` | 统一登记界面和战斗素材 |
| `game/Almanac.java` | 图鉴选择、分页、详情 GIF 和暂停 |
| `game/AlmanacDescriptions.java` | 中文名称与能力介绍，数值复用游戏资料 |
| `tools/TextDrawing.java` | 选关和图鉴共用的文字居中绘制 |

界面输入回调改用具名监听器，现有鼠标拖放和参数读取逻辑继续复用原处理方法，不为每个按钮新增独立文件

## 验证与工作区

运行 `build.ps1 -Test` 会检查阳光数字与旧版样式逐像素一致、主菜单进入选关、点击开始、返回、键盘选择、翻页和编号缺口，也会运行原战斗和编辑器自检

选关文字额外覆盖 100%、125%、150% 和 200% 缩放，鼠标事件检查覆盖单击选择、双击进入、右键忽略、不同封面连击和空白区连击

`LevelScreenshotTest` 检查截图复制、关卡保存重读、选关封面实际取图、比例适配、外部原图删除后仍可读取、恢复自动、文件丢失回退与路径转义；测试结束删除临时图片和临时关卡

`AlmanacTest` 验证主页入口、所有植物与僵尸资料、翻页边界、键盘与鼠标切换、动画暂停恢复、返回后冒险模式正常，并比较不同时间的实际渲染像素以确认 GIF 在播放

`ConveyorRegressionTest` 通过樱桃实际引爆检查无掉头的灰烬死亡流程，并验证镜头移动期间隐藏传送带、停稳后向下入场、倒计时后启动战斗，以及长时间补卡、满队列和中间卡片使用后的补位边界

`JavaStyleTest` 检查源码中的自增自减、复合赋值、箭头写法、方法引用、三目运算、可变参数、匿名回调和注释末尾句号，并用代码片段核对规则是否会误判字符串和泛型通配符。功能与设计原因等注释语义仍需人工复核，自动检查不代替人工阅读

选关与图鉴通过 `TextDrawing.drawCentered` 共用文字定位；游戏的鼠标事件和自检点击通过 `Game.handleClick` 共用分派。植物和僵尸介绍都按内部名称查询，调整资料表顺序不会改变介绍的对应关系

编辑器通过 Gson 写入关卡，截图路径、卡池、禁用与必选清单、随机行和波次表格均保持原有字段。保存后的 JSON 使用统一缩进，读取仍兼容旧的手写格式

截图输出到已忽略的 `build/`：`level-selection.png`、`sun-numbers.png`。测试创建的临时关卡结束即删除，源码、素材和构建产物分别保留在 `src/`、`assets/`、`build/`
